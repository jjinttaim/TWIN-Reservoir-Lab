# 계산 모형과 확장 경계

## 시간과 단위

- 각 행의 timestamp는 구간 시작 t입니다. 유입과 방류량은 [t,t+Δt)의 평균 m³/s입니다.
- 계산 storageMcm와 levelM은 endTimestamp로 기록하는 구간 끝 t+Δt입니다. startStorageMcm/startLevelM은 시작 상태입니다.
- 관측 observedStorageMcm/observedLevelM은 timestamp 시점의 시작 상태입니다.
- observedGenerationMWh는 해당 구간의 에너지입니다. 계량기 누적값과 순간전력은 미리 변환해야 합니다.
- 단위: 저장량 백만m³, 유량 m³/s, 시간 hour, 수위/낙차 m, 전력 MW, 에너지 MWh.

## 물수지

기본 관계: S_end = S_start + (Q_in - Q_out) × Δt_seconds / 1,000,000.

가용 물이 부족하면 조절 방류량을 줄입니다. 최대 저수량을 넘는 물은 overflowCms로 기록하며 물수지에서 누락하지 않습니다. 전체 방류는 controlledReleaseCms + overflowCms입니다. spillCms는 총방류 중 발전을 거치지 않은 유량이며 실제 여수로만을 뜻하지 않습니다.

overflow는 수리학적으로 검증된 여수로 유량이 아닙니다. 이 모형은 물이 넘쳐나는 양을 보존하기 위한 단순화이고, 실제 댐의 월류, 파괴, 하류 침수 계산에 사용할 수 없습니다.

## 발전

P_MW = 1000 × 9.81 × Q_turbine × head × efficiency / 1,000,000.
E_MWh = P_MW × Δt_hours.

낙차는 구간 시작과 끝 수위 평균에서 방수로 수위를 뺀 값의 0 이상 부분입니다. 조절 방류만 발전 용량 안에서 발전에 우선 사용하며, 불가피한 넘침을 자동으로 터빈으로 돌리지 않습니다. 이는 운영 가정이므로 정책 비교 시 같은 가정을 적용해야 합니다. 실제 발전기의 효율곡선, 가동 상태, 최소 가동유량, 낙차 손실은 반영하지 않습니다. 실제 제원, 관측으로 검증하기 전에는 추정치입니다.

## 운영 방법

- fixed: 고정 방류량과 최소 방류 요구량 중 큰 값을 요청합니다.
- rule: 직전 구간 유입량과 현재 저수량의 목표 차이를 사용합니다. 첫 구간 유입 추정은 fixedReleaseCms입니다. 현재 구간 전체 평균이나 미래 유입량을 미리 읽지 않습니다. 목표 보정항은 `(S−target) × 1,000,000 × (1−exp(−Δt/T)) / Δt`이며 Δt, T는 초입니다. 이산화 때문에 일자료에서 발생할 수 있는 목표 초과 진동을 줄입니다. 방류 제한, 변하는 유입 조건에서는 목표 도달을 보장하지 않습니다.
- recorded: 입력된 총방류 기록을 요청합니다. 설정 제약 초과를 지우지 않으며 물이 부족하면 실제로 이행하지 못한 양을 명시합니다. 관측 발전유량이 없으면 발전 우선배분을 가정합니다.

첫 관측 저수량을 초기값 칸에 입력하는 버튼을 제공합니다. 설정 저장 때 범위를 검사합니다. 관측 수위와 저수량을 자동으로 덮어쓰거나 모델 보정에 사용하지 않습니다. 자료의 유입량이 저수량과 방류에서 역산됐다면 같은 자료와의 일치는 독립 검증이 아니라 자료 정합성 점검입니다. 관측재현은 검증 가능성을 마련한 기능이고, 실제 검증을 끝냈다는 뜻이 아닙니다.

## 추후 AI 연결

src/model.mjs의 요청 방류량 결정 부분을 정책 함수로 분리해 확장할 수 있습니다. 정책에는 그 시점에 이미 알 수 있었던 상태, 과거 관측, 발표된 예보만 전달해야 합니다. 미래 실제 유입량을 정책이 접근하면 비교가 부정확해집니다. 물수지, 물 부족, 월류, 발전 계산은 정책과 분리해 공통 적용합니다.

예측 모델을 붙일 때는 학습, 조정, 최종평가 기간을 분리하고, 단순 예측과 같은 기간과 지표로 비교합니다. 정책을 비교할 때는 같은 초기 물과 같은 가용 정보, 같은 제약을 사용합니다. 종료 저수량 차이를 함께 평가합니다.

## 실제 자료 적용 전 확인

1. 지점, 단위, 시간대, 시각의 의미 및 결측 처리
2. 유입량의 계산 방식과 총방류의 구성, 독립 계측 여부
3. 실제 수위–저수량 표 및 시설 제원
4. 초기 저수량과 모델 시작 시점 일치
5. 미포함 물수지 항목(취수, 증발, 누수 등)의 크기
6. 구간 시작/끝을 맞춘 관측 비교, 별도 기간 검증

학습된 AI, 탁수 모형, 실시간 관측 연결은 이 버전에 포함되지 않았습니다.

## 1.1의 3D 표시 계층

`src/viewer3d.mjs`는 위 물수지 계산 결과를 받아 그리는 표시 계층입니다. 3D 모델을 바꾸거나 카메라를 회전해도 방류 정책, 발전 계산은 바뀌지 않습니다. 수위는 장면에 정한 수면 높이 범위로 정규화하고, 총방류, 비발전 방류, 발전 방류는 각 물길의 시각효과 강도에 대응시킵니다. 물의 이동 속도, 물보라, 조명, 파도는 영상 표현이며 유체역학 계산 결과가 아닙니다.

특히 `spillCms`는 비발전 방류의 합계이므로 실제 여수로 위치, 게이트별 유량의 관측값으로 취급하지 않습니다. 실제 배수로별 분배나 구조물을 반영하려면 별도 관측, 시설 모델과 검증이 필요합니다. 자세한 파일 구조는 `3D_장면_안내.md`를 참고하세요.
